# 제품 요구사항 정의서

> 이 문서는 현재 구현된 코드를 기준으로 역으로 정리한 PRD입니다.

## 1. 제품 개요
- 제품명: react-composable-search
- 목적: 다양한 검색 조건(지역/키워드 등)을 조합해 선택할 수 있는 **컴포저블 검색 UI** 제공
- 형태: React 컴포넌트(라이브러리/샘플 앱 형태)

## 2. 문제 정의 및 가치
- 계층형 지역 선택과 키워드 등 복합 조건을 한 화면에서 조합하기 어렵다.
- 선택된 조건을 한눈에 확인하고 개별/전체 삭제할 수 있는 UI가 필요하다.

## 3. 목표
- 지역(시/도 → 시/군/구 → 읍/면/동) 기반 **다단계 선택** 제공
- 선택된 조건을 **칩 형태**로 가시화하고 빠르게 삭제 가능
- 선택 컨트롤을 **유형별로 조합 가능한 구조**로 제공

## 4. 대상 사용자
- 복합 검색 UI가 필요한 서비스(부동산, 로컬 검색, 행정/지역 기반 서비스)
- 해당 컴포넌트를 사용하는 프론트엔드 개발자

## 5. 핵심 사용자 시나리오
1) 사용자는 지역 선택을 열고 시/도 → 시/군/구 → 읍/면/동을 탐색한다.
2) 여러 읍/면/동을 체크하여 조건을 추가한다.
3) 선택된 조건은 하단 칩으로 표시되며, 개별 삭제/전체 삭제가 가능하다.
4) 키워드 조건은 버튼 형태로 제공되며(현재는 트리거만 존재), 클릭 후 입력 UI로 확장될 수 있다.

## 6. 범위 정의
### 포함 (현재 구현)
- ComposableSearch 컨테이너(선택 영역/상세 영역/선택 결과 영역 구성)
- 지역 선택 UI (3단 컬럼)
- 키워드 선택 버튼(트리거)
- 선택 조건 칩 표시 및 삭제/전체 삭제

### 제외/미구현
- 키워드 입력/검색 실행 UI
- “현재 지역 전체” 선택 로직 완성
- 실제 검색 결과 렌더링
- 외부 API 연동(데이터는 주입 함수로 공급)

## 7. 기능 상세

### 7.1 ComposableSearch
- **구성 영역**
  - 상단: 선택 셀렉터 영역
  - 중단: 상세 조건 영역(토글)
  - 하단: 선택된 조건 칩 + 전체 삭제 버튼
- **상태 관리**
  - 선택 조건 리스트를 내부 상태로 보관
  - 개별 조건 토글(추가/제거)
  - 전체 삭제 기능
- **지역 선택 규칙(현재 구현 기준)**
  - 일반 읍/면/동 선택: 동일 시/군/구의 “전체” 선택이 있으면 제거 후 토글
  - “전체” 선택 조건은 `sigungu.code === eupmyeondong.code` 기준으로 처리(현재 실제 생성 경로는 제한적)

### 7.2 RegionSelect
- 데이터 공급 함수 주입
  - `findAllSidos()`, `findAllSigungus(sidoCode)`, `findAllEupmyeondongs(sigunguCode)`
- 상세 조건 영역 토글 트리거
- 읍/면/동 선택 시 조건 생성
  - `displayName`: `시/도>시/군/구>읍/면/동`
  - `id`: 읍/면/동 코드

### 7.3 RegionSelectConditionsArea
- **3단 컬럼 UI**
  - 시/도: 선택형 리스트
  - 시/군/구: 선택형 리스트
  - 읍/면/동: 체크박스 리스트(다중 선택)
- 선택 상태 표시
  - 선택/현재 항목에 시각적 강조 적용

### 7.4 KeywordSelect
- 아이콘 + 플레이스홀더가 있는 버튼
- 클릭 이벤트만 제공(입력 UI는 미구현)

### 7.5 SelectedConditionBasket
- 선택된 조건을 칩으로 렌더링
- 개별 삭제 버튼 제공

## 8. 데이터 모델
- **Region**: `{ displayName, name, code }`
- **SelectedCondition**: `{ id, displayName }`
- **SeletedRegionCondition**: `SelectedCondition + { sido, sigungu, eupmyeondong }`
- **ComposableSelectItem (확장용)**: `{ type, displayName, value }` (현재 사용 최소)

## 9. UI/UX 요구사항
- 카드 형태의 컨테이너 레이아웃
- 셀렉터는 가로 배치, 아이콘 포함
- 상세 조건 영역은 토글(열림/닫힘) 가능
- 지역 리스트는 스크롤 가능해야 함
- 선택 조건 칩은 가독성이 높고 삭제 조작이 쉬워야 함

## 10. 상태/예외 처리
- 데이터 없음: “No items to display.” 표시
- 상위 선택이 없는 경우 읍/면/동 선택 불가
- 선택 조건 없음: 전체 삭제 버튼 비활성

## 11. 연동 및 확장 지점
- 외부 데이터는 **함수 주입 방식**으로 공급
- 추가 조건 유형을 `ComposableSelect` 구조로 확장 가능

## 12. 비기능 요구사항
- 클라이언트 단 UI 컴포넌트로 동작
- 중간 규모 리스트에서도 부드럽게 스크롤 가능
- 접근성: 버튼 포커스/키보드 접근은 추가 개선 여지 있음

## 13. 지표(향후 측정 가정)
